# 阶段 7.1：合规采集边界与最小采集方案

状态：待用户确认  
最后核对日期：2026-09-15

## 1. 这一阶段解决什么

在编写任何自动采集代码前，先确定数据来源、允许采集的字段、人工确认点、停止条件和模块隔离方式。

本阶段只形成设计结论，不登录招聘平台、不抓取页面、不调用隐藏接口，也不修改现有数据库和前后端功能。

## 2. 当前结论

### BOSS 直聘：仅允许人工导入

BOSS 直聘现有公开用户协议明确限制：

- 未经许可，不得通过第三方工具获取平台服务；
- 未经许可，不得使用蜘蛛、爬虫、拟人程序或规避技术措施的方式读取、复制、转存平台信息；
- 不得自动登录、复用账号给第三方工具使用，或绕过平台流程和限制。

因此，本项目目前不为 BOSS 直聘开发网页爬虫、浏览器自动读取、登录态复用或隐藏接口采集。即使降低访问频率，也不能改变这一边界。

允许的最小流程是：用户正常浏览岗位，手动复制自己需要分析的岗位文字，再通过现有粘贴、TXT 或 CSV 功能导入本地。

### 其他来源：逐个审核后进入允许名单

未来自动采集只考虑以下来源：

1. 明确提供且允许当前用途使用的官方 API、RSS、数据下载或开放数据集；
2. 平台规则、网站条款与 robots 声明均未禁止，且不需要登录的公开招聘页面；
3. 公司自己的招聘官网，但仍须逐站核对条款、robots 与访问限制；
4. 用户合法持有并主动导入的 TXT、CSV 等文件。

robots 未禁止不等于自动获得授权。只要来源规则不清楚，就保持 `paused_review`，不采集。

## 3. 可保存与默认排除的数据

### 可保存的岗位字段

- 原始岗位名称
- 公司名称
- 原始 JD 正文
- 来源平台
- 原始公开链接
- 发布时间与采集时间
- 地区与薪资区间
- 内容指纹、重复状态和岗位分类
- 来源审核状态、规则核对日期

只保存岗位分析实际需要的最少信息，不保存完整网页 HTML、广告脚本、埋点参数或与岗位无关的页面内容。

### 默认不得采集或保存

- 招聘者姓名、头像、手机号、邮箱及其他联系方式
- 招聘者账号 ID、聊天记录、私信和沟通状态
- 候选人简历、联系方式、投递记录等第三方个人数据
- Cookie、登录令牌、请求签名、设备标识和浏览器指纹
- 验证码、隐藏接口响应及登录后但未由用户主动导出的数据
- 与岗位分析无关的任何个人信息

导入文本若意外包含上述内容，应在预览阶段提示删除或脱敏；无法安全处理时拒绝导入。

## 4. 数据来源状态

每个来源必须处于以下一种状态：

| 状态 | 含义 | 系统行为 |
| --- | --- | --- |
| `manual_only` | 只允许用户手动复制或导入 | 不发起网络请求 |
| `allowed_automated` | 已确认存在明确许可的自动获取方式 | 仅按批准的适配器运行 |
| `paused_review` | 条款不清楚、规则变化或出现异常 | 暂停全部自动访问 |
| `blocked` | 明确禁止或存在高风险 | 不实现、不运行该来源适配器 |

初始设置：BOSS 直聘为 `manual_only`，其余来源默认为 `paused_review`。

## 5. 最小可行采集方案

### 第一步：保持现有人工导入

- BOSS 直聘继续使用手动复制、TXT 和 CSV 导入；
- 导入前显示字段预览与疑似个人信息提示；
- 用户确认后才写入正式岗位库；
- 继续使用现有内容指纹和近似重复识别。

### 第二步：开发独立的半自动采集助手

半自动助手不以 BOSS 直聘为目标。先选择一个拥有官方 API、RSS、下载文件或明确允许自动访问的来源作为试点。

工作流：

1. 获取公开岗位数据；
2. 写入隔离的暂存区；
3. 标准化字段、脱敏、去重；
4. 用户预览并确认；
5. 由主应用导入正式岗位库。

未经人工确认，采集结果不得直接进入岗位画像统计。

### 第三步：通过验收后再考虑定时采集

只有半自动流程连续稳定、来源规则仍允许、失败日志和停止机制均有效后，才讨论定时运行。定时采集不是 7.1 的实现范围。

## 6. 未来获准来源的访问控制

以下是工程安全默认值，不代表平台授权，也不能覆盖来源自身规则：

- 单域名串行访问，默认每 10～30 秒最多一个请求并加入随机间隔；
- 优先使用 ETag、Last-Modified、缓存和 URL 指纹，避免重复下载；
- 以来源公布的更严格限制为准；
- 收到 `401`、`403`、`429`、验证码或风控页面时立即停止，不切换代理、不伪装设备、不反复重试；
- 普通网络错误采用逐级退避，连续 3 次失败后将来源改为 `paused_review`；
- 每个来源具备单独的关闭开关和每日上限；
- 规则或页面结构变化时先暂停，再人工复核。

## 7. 必须保留的人工确认点

1. 新来源加入允许名单前，确认官方条款、robots、是否登录以及允许用途；
2. 首批结果进入岗位库前，确认字段映射和个人信息清理结果；
3. 系统识别为近似重复时，由用户决定保留、合并或忽略；
4. 系统建议岗位分类后，由用户确认；
5. 来源条款变化、出现封禁信号或采集异常后，由用户决定是否恢复。

## 8. 与主应用隔离

未来采集模块应作为独立目录和独立进程运行，不成为 FastAPI 主服务的启动依赖。

- 暂存数据建议放在 `D:\AI\resume-tailor-data\collector-staging\`；
- 采集模块只输出经过定义的 JSONL 或导入包；
- 主应用只读取校验通过并经用户确认的导入包；
- 采集失败不会阻止岗位查看、分析、简历生成和导出；
- 每个来源可独立关闭，不影响其他来源；
- 日志只记录时间、来源、URL 指纹、错误类别和重试状态，不记录 Cookie、令牌和个人信息。

## 9. 失败与重复记录

采集记录至少包含：

- 来源、采集时间和规则版本
- 成功、失败、暂停或人工拒绝状态
- 错误类型，不保存敏感响应正文
- 内容指纹和标准化链接
- 完全重复、正文相同、同公司重复发布或近似重复
- 最终是否进入正式岗位库及人工确认结果

失败数据先留在暂存区，默认保留 30 天后清理；正式岗位样本由用户主动删除。保留期限以后应允许配置。

## 10. GitHub 公开边界

公开仓库只包含采集架构、字段定义、脱敏示例和测试样本，不包含：

- 私人简历和个人事实素材
- 真实岗位数据库或批量原始 JD
- 登录信息、Cookie、令牌和本地配置
- 含招聘者个人信息的截图或日志

个人数据继续保存在 D 盘数据目录，并由 `.gitignore` 排除。未来配置文件只提交示例版本，真实密钥和本地路径不得进入 Git。

## 11. 来源审核清单

新来源必须逐项填写：

- 来源名称和入口 URL
- 数据获取方式：手动、API、RSS、下载文件或公开网页
- 是否要求登录
- 官方条款是否明确允许当前用途
- robots 是否允许对应路径
- 是否包含个人信息
- 允许字段和禁止字段
- 请求频率与每日上限
- 异常停止条件
- 规则核对日期和证据链接
- 最终状态：`manual_only`、`allowed_automated`、`paused_review` 或 `blocked`

任何关键项不明确，最终状态只能是 `paused_review`。

## 12. 7.1 完成标准

- 明确 BOSS 直聘当前只做人工导入；
- 明确允许字段、禁止字段与个人信息处理方式；
- 明确自动来源必须先进入允许名单；
- 明确访问频率、异常停止和人工确认点；
- 明确采集暂存区与主应用隔离；
- 明确 GitHub 不公开私人数据和真实批量岗位库；
- 本步骤没有新增爬虫代码、数据库迁移或页面功能。

## 13. 依据与限制

- [BOSS 直聘用户协议及隐私政策](https://www.zhipin.com/web/common/protocol/protocol-2019-09-30.html)：第五条第 8 项、第八条第 10、13、14 项等涉及第三方工具、爬虫、规避技术措施与自动登录限制。
- [网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)：涉及数据合法获取、自动化访问影响、个人信息最小化及不得规避技术措施等要求，自 2025-01-01 起施行。
- [个人信息保护政策法规问答（2026 年 1 月）](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)：说明职业、职务、账号等信息可能构成个人信息。

本文件是项目工程边界，不是法律意见。平台规则和法律可能变化；任何来源启用自动采集前，都必须重新核对当时有效的官方规则。
