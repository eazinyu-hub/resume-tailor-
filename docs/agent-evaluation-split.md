# Agent 评估测试集（6.1 设计）

## 目的

测试集用于检查岗位画像、相似 JD 检索和简历建议是否真的更贴近未见过的 JD，而不是只验证它们能复述已参与统计的样本。

这里的“测试”是产品评估，不是训练模型；Agent V1 当前没有训练或微调步骤。

## 划分原则

- 只使用有效、去重后的真实 JD 样本。
- 同一正文、近似重复发布、同公司同岗位的重复版本必须进入同一侧，不能一条进画像、一条进测试集。
- 按岗位方向分层抽取，避免测试集只剩某一种岗位。
- 一旦冻结测试集，后续岗位画像、关键词频率、相似 JD 基线都不得读取它。
- 测试集中的 JD 可以用于人工评分，但不能反过来成为市场画像证据。

## 当前阶段：只定义，不冻结

当前有效样本不足 50 条时，不划分正式测试集。原因是分走少量 Vibe Coding、Agent 等稀缺方向样本，会明显降低市场画像的稳定性。

可以保留少量“候选测试 JD”作人工演练，但页面必须标记为**非正式评估**，不能据此宣称 Agent 已经变准。

## 正式冻结门槛

当有效、去重后的样本达到至少 50 条，且主要岗位方向各有足够样本时：

| 集合 | 建议数量 | 用途 |
| --- | ---: | --- |
| 岗位画像集 | 约 80%，例如 40 条 | 生成关键词、方向画像、相似 JD 基线 |
| 冻结测试集 | 约 20%，例如 10 条 | 只用于评估，不参与任何统计或检索 |

若某个方向样本过少，优先继续收集，不为凑比例拆走该方向唯一的几条样本。

## 冻结时需要保存的元数据

- `evaluation_split`：`profile`、`holdout` 或 `candidate`。
- `split_version`：本次划分版本。
- `frozen_at`：冻结时间。
- `split_reason`：例如“按岗位方向分层抽样”。

这些字段属于岗位元数据，原始 JD 永远不改写。

## 本小步完成标志

- 明确什么时候可以划分、什么时候不能划分。
- 明确冻结测试集不参与画像与检索。
- 未修改现有岗位数据、数据库和页面。
