# Agent 回归案例（6.3）

## 目的

每次修改岗位分类、要求识别、相似检索或事实匹配后，都重新运行同一批固定案例。只要曾经修复的问题再次出现，测试就会失败，避免新优化悄悄破坏旧能力。

回归案例不是岗位画像样本，也不是训练数据。它们是脱敏的合成输入，只保留真实问题的结构，不包含招聘公司、真实 JD、个人简历或个人项目内容。

## 文件

- 机器可读案例：`backend/tests/fixtures/analysis_regression_cases.json`
- 自动执行入口：`backend/tests/test_saved_regression_cases.py`
- 现有细粒度测试：`backend/tests/test_analysis_quality.py`

固定案例有独立的 `suite_id` 和 `schema_version`。修改预期结果时，必须说明算法口径为什么改变；不能为了让失败测试通过而直接把错误输出改成新答案。

## V1 保存的错误类型

| 类型 | 防止再次出现的问题 |
| --- | --- |
| 岗位分类 | 产品岗位因提到 Agent 被误分；上下文工程师默认进入全栈；Vibe Coding 空格匹配失效；无法识别的岗位被强行分类 |
| 要求识别 | “无需 Python”被算成要求；加分项被当作硬要求 |
| 任选条件 | “至少一种语言”被拆成多项缺口；“至少两种工具”只命中一种就判断满足 |
| 事实边界 | 岗位分类功能被当成实现 Agent；关键词统计被当成使用该技术；计划、失败和禁止项被当成已完成 |
| 相似检索 | 只因方向相同就凑数；当前 JD 或相同正文进入自己的参考样本 |

## 运行方式

在 `D:\AI\resume-tailor\backend` 中运行：

```powershell
$env:PYTHONDONTWRITEBYTECODE = "1"
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

完整测试会同时运行保存的回归案例和原有单元测试。临时数据库创建在仓库的 `work/` 目录中，该目录已被 Git 忽略。

## 新增案例规则

以后遇到真实错误时：

1. 先把错误结构改写成不含私人信息的最小合成案例。
2. 给案例添加稳定 ID、原问题说明、输入和预期结果。
3. 先确认旧代码会失败，再修算法。
4. 运行整套测试，而不只运行新案例。
5. 案例与修复代码一起提交 Git。

不能把完整真实 JD 或个人事实卡复制进仓库。若错误依赖特殊排版，只保留复现错误所需的最短文本。
