# 阶段 7.6-A：采集前防重复保护

状态：待用户确认  
实现日期：2026-09-17

## 本步骤完成的内容

- Greenhouse、Lever、Moka 共用同一套暂存去重规则；
- 优先使用“来源平台 + 来源岗位 ID”识别同一岗位；
- 同一岗位且内容指纹相同时跳过，不重复写入待确认区；
- 同一岗位正文变化时保留为新版本，并关联上一版内容指纹；
- 新版本在待确认页面显示核对提醒；
- 新增、跳过和发现更新都会写入 D 盘本地采集事件日志；
- 没有来源岗位 ID 的记录仅使用内容指纹兜底。

## 数据边界

- 去重只影响 D 盘采集暂存区；
- 不自动导入、修改或删除正式岗位；
- 已经人工处理过的相同版本再次采集时仍会跳过；
- 更新版本必须继续经过人工确认。

## 完成标准

- 重复运行同一条采集命令，暂存记录数量不增加；
- 同一来源岗位正文变化后，会新增一条带更新提醒的记录；
- 采集事件日志能够说明新增、跳过或更新原因；
- 原有采集、审核和导入流程继续可用。
