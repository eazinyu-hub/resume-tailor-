# 岗位分析规则校正

本轮修正岗位分类、画像、相似检索和事实匹配的口径，不改原始岗位、简历或个人事实卡，不自动生成或覆盖简历。

## 数据和画像

- 原始记录全部保留。统计排除无效记录、已标记重复记录，以及正文经 NFKC / 空白归一后相同的记录。
- 人工确认分类优先；未确认时结合岗位标题与正文建议方向。无法识别的记录进入“待确认方向”，不默认算全栈。
- 按职责、任职要求、正文提及和加分项保留原文依据；过滤规则能识别的否定与福利介绍。识别结果仍需人工核对。
- 画像中的共性至少需 2 份样本支持且占该方向 40%。少于 5 份时提示仅作初步观察。
- 扩充 MCP、RAG、Prompt、工具调用、Dify、Coze 等信号。市场关键词频率仍统计“提及”，不是硬性门槛。

## 三种分数不是同一件事

| 输出 | 含义 |
| --- | --- |
| JD 相似分 | 按技术、工具、职责等信号做加权 Jaccard 比较，结合本批样本的词项稀有度，范围 0–100，仅用于选择参考 JD |
| 简历文字覆盖率 | 当前 JD 中被识别的非学历、非加分要求，在原始简历文字中覆盖的比例；不验证经历真实性 |
| 直接项目事实覆盖率 | 同口径要求有直接已验证项目事实支持的比例；事实卡若仍为草稿，依然不能写入正式简历 |

相似检索优先同方向，至少共享两项信号，低于 0.12 的相似度不凑数。当前岗位及相同正文不参与自己的参考画像。以上阈值是可复查的规则默认值，未经独立测试集证明最优。

对明确写明“至少一种/两种”等的编程语言、AI 工具选项，匹配时合并为一项，并检查满足选项数量；市场词频仍分别统计每种工具。没有可计分要求时返回空值而非伪造 0% 或 100%。

## 真实性边界

- 已实现功能、已使用技术、调试方法可作为直接证据；问题背景和失败描述本身不能证明实现能力。
- “计划实现”“需要补充”“禁止写入简历”不作为已完成事实。
- “支持 Agent 岗位分类”“统计 Python 关键词”不等于实现 Agent 或使用 Python 开发。
- 学历、任职年限等不由项目事实推断，单独提醒核对。
- 项目候选描述引用已验证事实原文，不插入通用功能模板；岗位介绍和建议随目标要求变化。
- 目前是本地规则与检索分析，准备了模型输入包，但尚未调用大模型、训练模型或验证整体推荐准确率。少量同类样本不代表完整招聘市场。

## 验证

后端回归测试使用独立临时目录中的合成数据，覆盖重复排除、不同岗位差异、任选条件、负面事实、草稿卡限制与数据库只读等情形。前端需通过 TypeScript / Vite 构建，并人工检查岗位切换、展开收起及对应岗位内展示。真实样本只在本地作核对，不进入仓库；冻结测试集的独立评估尚需后续完成。
