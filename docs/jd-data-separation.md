# JD 原始数据与分析结果分层（V1）

## 1. 目的

本设计用于明确岗位样本中的“招聘方原文”和“系统分析结论”之间的边界，避免重新分析、算法升级或人工修改时破坏原始 JD。

本小步只确定规则，不修改 SQLite、接口、前端或现有岗位数据。

## 2. 两层数据的职责

| 数据层 | 负责保存 | 数据来源 | 是否允许系统覆盖 |
| --- | --- | --- | --- |
| 原始岗位数据（Raw） | 招聘方原文及采集事实 | 用户输入、文件导入、未来的采集器 | 不允许 |
| 派生分析结果（Analysis） | 系统从 JD 中提取或推断的结构化结果 | 规则、模型、Agent、人工确认 | 未确认结果可以重新生成；已确认结果不能静默覆盖 |

## 3. 原始岗位数据规则

### 3.1 原始层保存什么

- 原始岗位名称
- 原始公司名称
- 完整原始 JD
- 来源平台和原始链接
- 页面显示的发布时间
- 实际采集或录入时间
- 地区和薪资原文
- 内容指纹
- 重复关系
- 样本状态

### 3.2 原始层的写入原则

1. 首次录入时创建一份原始记录。
2. 系统分析只能读取原始记录，不能修改原文。
3. 去除多余空格、统一换行等处理仅用于计算内容指纹，不回写原始正文。
4. 如果用户明确修正录入错误，需要记录更新时间；不能因为分析结果不同而自动改写原文。
5. 同一岗位出现新版本时，优先保存为新样本，并记录它与旧样本的关系，而不是覆盖旧版本。

## 4. 派生分析结果规则

### 4.1 分析层保存什么

- 标准岗位方向
- 岗位侧重点摘要
- 主要职责
- 硬性要求
- 加分项
- 技术与 AI 工具
- 工作经验要求
- 学历要求
- 支撑结论的 JD 原文片段
- 分析状态
- 分析器版本
- 分析时间

### 4.2 分析层的写入原则

1. 每次分析必须关联一条原始岗位记录。
2. 分析结果不得写回原始 JD 字段。
3. 自动分析结果必须记录分析器版本和分析时间。
4. 重要结论应保存对应的 JD 原文证据。
5. 尚未人工确认的分析可以重新生成。
6. 已人工确认的分析不能被后台任务静默覆盖。
7. 对已确认结果重新分析时，应生成新的候选结果，等待用户比较和确认。

## 5. 分析状态

V1 使用四种状态：

| 状态 | 含义 | 是否可以自动替换 |
| --- | --- | --- |
| `pending` | 尚未生成分析 | 可以生成 |
| `generated` | 系统已生成，尚未人工确认 | 可以重新生成 |
| `confirmed` | 用户已经确认或修改 | 不可以静默替换 |
| `failed` | 分析失败，保留错误状态以便重试 | 可以重试 |

## 6. 数据流

### 6.1 新增岗位

```text
用户粘贴或导入 JD
→ 保存原始岗位数据
→ 计算内容指纹
→ 判断是否重复
→ 创建 pending 分析状态
```

### 6.2 自动分析

```text
读取原始 JD
→ 提取职责、要求、工具和岗位方向
→ 为结论保存原文证据
→ 写入派生分析结果
→ 状态变为 generated
```

### 6.3 人工确认

```text
用户查看分析结果
→ 保留、修改或删除错误结论
→ 确认结果
→ 状态变为 confirmed
```

### 6.4 重新分析

```text
generated 结果
→ 可以直接重新生成

confirmed 结果
→ 保留已确认版本
→ 生成新的候选结果
→ 用户决定是否替换
```

## 7. 重复岗位的处理

- 完全相同的 JD 使用内容指纹识别。
- 重复记录仍可保留来源、链接和采集时间，但标记为 `duplicate`。
- 重复记录默认复用主样本的分析结果，不重复消耗分析资源。
- 如果正文发生实质变化，则保存为新的原始样本，后续再判断是否属于近似重复。
- V1 只保证完全重复识别，近似重复留到批量导入阶段实现。

## 8. 现有数据的边界

当前 `jobs` 中已有的 8 条岗位记录视为原始岗位数据：

- `title` 视为原始岗位名称。
- `description` 视为原始 JD。
- `source` 视为原始来源。
- `created_at` 视为首次录入时间。

现有关键词、重点识别、匹配度和建议属于派生结果。后续迁移时不得根据这些分析结果修改 `jobs.description`。

## 9. 允许和禁止的操作

| 操作 | 是否允许 | 说明 |
| --- | --- | --- |
| 查看原始 JD | 允许 | 原样展示招聘方正文 |
| 使用原始 JD 重新分析 | 允许 | 生成新的派生结果 |
| 自动修改原始 JD | 禁止 | 防止失去事实来源 |
| 修改未确认分析 | 允许 | 可以重新生成或人工编辑 |
| 静默覆盖已确认分析 | 禁止 | 必须让用户选择 |
| 删除分析后重新生成 | 允许 | 不影响原始岗位数据 |
| 使用市场画像补充当前 JD 原文 | 禁止 | 只能明确标记为“同类岗位常见要求” |

## 10. 验收标准

- 能清楚判断每个字段属于原始层还是分析层。
- 重新分析不会改变招聘方原文。
- 已确认结果不会被自动覆盖。
- 每个重要分析结论可以追溯到 JD 原文。
- 现有 8 条岗位可以被视为原始记录，无需重建或删除。
- 市场统计结论和当前 JD 原文不会混在一起。

## 11. 本小步不做的内容

- 不设计具体 SQL 建表语句。
- 不修改数据库。
- 不迁移现有岗位。
- 不修改前后端。
- 不实现分析版本比较页面。
- 不实现批量导入或自动采集。
