# 小步骤 3.2：按岗位方向生成样本画像

页面将纳入的 JD 分到六个岗位方向，分别展示：技术栈、AI 工具、工作职责、项目类型、学历与经验、交付能力。

每个条目显示“提及 JD 数 / 当前方向样本数”和占比；展开后可回看对应岗位和原文片段。

## 分类来源

1. 有人工确认的岗位，使用确认分类。
2. 未确认岗位，使用可解释关键词建议分类，并在页面显示建议分类数量。

本次开始统一岗位详情的分类建议和画像的建议分类规则。关键词例如“产品经理”“一人公司”“Agent 开发”“全栈”“自动化”有不同权重，标题和更明确的岗位词权重更高，减少“产品经理 JD 提到 Agent 就被归成 Agent 开发”的误判。

## 统计边界

- 与 3.1 相同，排除已确认重复、无效、空正文及忽略空白/大小写/全半角后相同的正文。
- 六类内容只统计 JD 正文提及，并不判断该词属于职责、硬性要求、加分项或否定句。
- 系统不写入岗位、分类或分析结果；接口只读 D 盘 SQLite。
- 样本少的方向只代表当前已收集岗位，不代表整个招聘市场。

## 验证

- 测试覆盖人工确认优先、未确认岗位建议分类、产品经理与 Agent 场景冲突、各类画像字段和原文证据。
- 前端构建通过；页面支持方向切换、收起/展开、刷新和定位到原始 JD。
