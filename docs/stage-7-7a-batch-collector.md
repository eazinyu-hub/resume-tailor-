# 阶段 7.7-A：工作台一键批量采集

本步把已有试采代码连接成用户可以自行运行的产品功能；不启用定时任务。

## 可验收路径

进入“采集待确认”页面，在“一键批量采集”中选择来源、方向和数量，点击“开始采集”。
后台自动读取、筛选、去重、暂存；页面显示进度、筛选理由、重复和失败。
切换页面或刷新不会创建新任务。关闭后端会中断任务，下次打开明确标记中断，不自动重跑。

- 默认工具自动化和 Vibe Coding；可选择 Agent 开发。
- 默认每源处理 30 条、最多暂存 10 条；硬上限分别为 100 / 20。
- 默认只暂存通过初筛的岗位；可主动选择同时暂存“条件待核实”。
- 通过初筛不等于已满足所有要求、仍在招聘的长期保证或录用概率。
- 只加入待确认区，人工确认后才进入正式库及后续画像。
- 没有合适岗位时允许结果为零，不补入高门槛岗位凑数。

## 来源覆盖的真实限制

从服务器审核登记表生成可选来源，不再把批量流程写死为单家企业。
本次没有新增企业白名单：Moka 元戎启行默认选中；Greenhouse Anthropic、
Lever K Group Companies 仅作为可选海外参考，默认不选。
这些是已有可读取来源，不代表适合入门转行；低门槛来源扩展仍是后续工作。
不提供任意网址输入、不自动搜索全网，也不采集 BOSS 登录页面。

Greenhouse 单次公开列表可能返回全表，本地只处理上限内岗位，并限制响应 5 MB；
不把“最多处理 30 条”说成服务端只传输 30 条。Lever/Moka 使用服务端 limit。
超过本次范围明确标注截断，不作全量扫描承诺。

参考：
- [Greenhouse 官方公开列表说明](https://docs.greenhouse.io/job-board.html#list-jobs)
- [Lever 官方 Postings API](https://github.com/lever/postings-api#get-a-list-of-job-postings)
- [Moka 官方 API 入口](https://www.mokahr.com/docs/api/)（沿用已审核的列表客户端）

## 筛选和安全边界

使用私有个人条件，不外发简历或个人资料。方向匹配以后先检查学历、专业、院校、经验，
硬冲突、高级岗位和研究路线排除，不以 AI 关键词分数抵消硬门槛。
经验未写明、资格待确认、外文要求等进入“待核实”，不默认零经验适用。
优先条件不作为硬冲突。单条规则识别仍可能遗漏，完整 JD 最终由用户审核。

每次只运行一个任务、串行访问来源，每源至少间隔 10 分钟；403/429 延长到 30 分钟。
读取失败不快速重试，一个来源失败不影响其他来源。请求无登录、Cookie、代理或验证码绕过。
新公开列表读取不跟随 HTTP 重定向；Moka 沿用现有主机校验与冷却保护。

正文指纹用于正式库和暂存历史去重；原有同源岗位版本保留机制继续有效。
暂存新增同步锁，避免后台采集与前台审核在同一进程内同时改写文件。
当前支持一个后端进程 / worker，不支持多进程或多机器同时写同一数据目录。

## 数据位置与实现

- `<DATA_DIR>/collector-runs/state.json`：最近 20 次任务、筛选摘要、冷却时间和上次配置。
- `<DATA_DIR>/collector-staging/`：完整 JD、来源和批量初筛标记，以及已有审计日志。
- Windows 使用既有 `D:\AI\resume-tailor-data`；Linux 用 `DATA_DIR` 指定绝对私有目录。
- 上述目录均不进入 Git；测试使用仓库中已忽略的 `work/`，不污染个人库。

`collector/batch_sources.py` 负责已审核源的单页读取；`collector/batch.py` 负责任务编排，
`app/collection_gate.py` 负责门槛判断，`BatchCollectorPanel.tsx` 提供配置、进度和记录。
以后定时器可调用同一任务流程，本步没有创建任何系统计划任务。

新增接口：`GET /api/collector/batch`、`POST /api/collector/batch/runs`、
`GET /api/collector/batch/runs/{run_id}`。启动立即返回 202，任务在后台执行。
