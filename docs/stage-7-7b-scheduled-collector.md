# 阶段 7.7-B：应用内定时采集

沿用 7.7-A 的批量管线：读取已审核来源 → 方向和个人门槛筛选 → 去重 → 待确认。
本步不增加采集企业，不自动确认入正式库，不创建 Windows 计划任务或 Codex 自动任务。

## 用户如何操作

1. 打开“岗位采集 / 待确认”，先选来源、方向、每源处理上限、每轮暂存上限。
2. 在“定时采集”选择每 1 / 6 / 12 / 24 小时（默认推荐 6 小时），点击“启用定时采集”。
3. 查看已保存的配置、北京时间的下次运行时间和倒计时。第一次执行在一个周期之后，不立即抓取。
4. 点击“暂停定时采集”阻止后续任务。已经开始的一轮仍在原上限内完成。
5. 自动结果使用同一个任务记录和待确认区，仍需人工预览、确认入库。

默认暂停，必须主动启用。启用/保存时对上方采集配置拍快照；仅修改手动采集表单不会
偷偷改变定时任务。修改频率或点击保存会重新从当前时间安排下次运行。暂停保留配置。

## 运行与失败边界

- 由 FastAPI lifespan 管理一个后台线程，每 15 秒检查一次本地计划，不是每 15 秒访问招聘网站。
- 网页关闭不影响执行；后端停止、电脑关机/休眠时不能采集。不负责系统开机自启。
- 已启用配置持久化；后端重启保留未来时间，错过的周期跳过，重新安排一个完整周期，不补跑积压。
- 手动和定时共用单任务锁、来源冷却和数量上限；忙碌或冷却中会延后，不并行抓取。
- 每源仍至少间隔 10 分钟，403/429 沿用 30 分钟冷却，不做快速重试；后续仍按计划周期尝试。
- 来源列表不变，不自动翻页，不使用登录态、代理轮换、验证码绕过；BOSS 继续手动导入。
- 个人配置/任务准备异常会暂停；执行异常记录在任务中。配置损坏不覆盖原文件，不影响主应用启动。
- 网络期间不持有定时控制锁，暂停请求仍可响应；已经领到的一轮不会被强制中断。
- 仅支持一个后端进程/worker，不支持多进程或多台机器共用数据目录。部署不要启用多个 uvicorn worker。

## 实现与存储

- `backend/collector/scheduler.py`：计划持久化、启动恢复、调度和暂停。
- `backend/app/main.py`：应用生命周期和三条定时 API。
- `frontend/src/CollectionSchedulePanel.tsx`：配置快照、频率、暂停、运行时间和状态。
- `GET /api/collector/schedule`、`PUT /api/collector/schedule`、`POST /api/collector/schedule/pause`。
- `<DATA_DIR>/collector-runs/schedule.json`：私有计划；现有 `state.json` 保留最近 20 次手动/定时任务。
- Windows 使用 `D:/AI/resume-tailor-data`；Linux 通过 `DATA_DIR` 指定持久化私有目录。
- 所有计划、采集内容、测试数据在忽略目录，不进 Git。不将个人简历发往招聘来源。

调度器启动遵循 [FastAPI 官方 lifespan 说明](https://fastapi.tiangolo.com/advanced/events/)。

## 验证范围

离线测试使用隔离目录和模拟时钟，覆盖到期自动运行、限量、去重、暂停、恢复、重启跳过积压、
手动冲突、冷却延后、读写失败、失效个人配置、网络失败和并发 tick。不会为测试生成正式岗位。
API 测试验证启用不立即采集、严格频率校验、暂停持久化以及 lifespan 启停执行器。

本步验证的是定时管线能否工作，不代表招聘来源变多或岗位门槛自动降低；
接下来仍需单独扩展更适合零相关经验、非计算机专业的已审核来源。
