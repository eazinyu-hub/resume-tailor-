# 两个岗位、两种侧重点（脱敏固定示例）

本示例使用合成 JD、合成简历和公开事实卡，不包含真实公司或个人信息。它展示的是经过固定回归测试的预期行为，不冒充真实 DeepSeek 调用截图。

## 共用项目事实

- 实现岗位批量导入、重复识别和人工确认流程。
- 实现可设置频率、暂停状态和单次上限的定时采集流程。
- 使用 React、FastAPI 和 SQLite 实现前端页面、后端接口与本地数据存储。
- 实现岗位级草稿编辑以及 Word 和 PDF 导出。
- 禁止写成已有真实招聘客户或大规模线上用户。

## 岗位一：AI 工具与自动化专员

JD 重点：内部工具、自动化流程、批量数据处理、重复识别、定时任务和结果验证。

候选侧重点：工具自动化侧重点。

- 实现岗位批量导入、重复识别和人工确认流程。
- 实现可设置频率、暂停状态和单次上限的定时采集流程。

为什么这样改：先展示批量处理、自动任务控制和人工审核闭环；不把 React 或页面开发放在第一优先级。

## 岗位二：Vibe Coding 全栈工程师

JD 重点：使用 AI Coding 把想法做成可运行产品，独立完成前端、后端、存储、调试和导出。

候选侧重点：Vibe Coding 全栈侧重点。

- 使用 React、FastAPI 和 SQLite 实现前端页面、后端接口与本地数据存储。
- 实现岗位级草稿编辑以及 Word 和 PDF 导出。

为什么这样改：先展示从页面、接口、存储到可交付文件的全栈产品闭环；不把定时采集放在第一优先级。

## 对比结论

两份描述没有虚构两套项目，也没有只替换岗位名称。它们引用同一组已验证事实，但根据 JD 改变了事实选择、排序和修改理由。
